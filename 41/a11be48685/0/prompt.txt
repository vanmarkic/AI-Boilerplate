### BLOCKER

**File:** `/Users/dragan/Documents/AI-Boilerplate/apps/tfc/frontend/src/app/core/exercise.store.ts:31`

**Issue:** `ScoreState.penaltyMs` is always written as `0` — hardcoded in both `applySnapshot` (line 182) and `applyScoreChange` (line 289) — and never updated by any incoming change. The field appears to have been kept as a structural placeholder, but it actively misleads: the `ScoreBarComponent.ScoreState` interface (in `/Users/dragan/Documents/AI-Boilerplate/apps/tfc/frontend/src/app/shared/score-bar.component.ts:16`) declares `penaltyMs?: number` and at line 84 triggers a UI shake animation `if (s.penaltyMs && s.penaltyMs > 0)`. ### `score-bar.component.ts` changes

The `ScoreState` interface in `score-bar.component.ts` defines `stress?: number` (optional), while the internal `ScoreState` in `exercise.store.ts` defines `stress: number` (required, always present once score is set). The player view passes `store.score()` (from the store) directly to `[score]` on `<tfc-score-bar>`. TypeScript will accept this because the store's type is structurally a subtype of the component's interface (a required field satisfies an optional field).

🟡 **The `@if (score()?.stress != null)` guard in the score-bar template** is unnecessary given that `StressBarComponent` already handles `stress=0` gracefully and `stress` is always present on the store's `ScoreState`. The guard is benign but adds noise — it exists to handle the `stress?: number` optionality in the component's own interface, which was presumably added to remain backward-compatible. This is fine as-is, just slightly defensive.
